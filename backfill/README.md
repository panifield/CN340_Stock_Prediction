# backfill/ — log ทำนายย้อนหลังของวันที่ระบบอัตโนมัติพลาด (ตั้งแต่ 2026-09-28)

**ไม่ใช่ log จริง** — ทุกแถวในโฟลเดอร์นี้ทำนายย้อนหลังหลังรู้ผลแล้ว (`generated_at` = เวลาที่รัน backfill
ไม่ใช่เวลาของวันนั้น) และมีคอลัมน์ `is_backfill=True` ติดทุกแถว **ห้ามนำไปปนกับ `task_*/results/prediction_log*.csv`**
ถ้างานนี้ต้องใช้หลักฐานว่าทำนายสดตามเวลาจริง ให้ใช้ log จริงเท่านั้น

ไม่ได้แก้ไฟล์ใดใน `task_*/` และ `automation/` เลย (เพิ่มเฉพาะโฟลเดอร์ `backfill/`)

## วิธีทำงาน
สคริปต์ [run_one.py](run_one.py) "ครอบ" ฟังก์ชันดึงข้อมูลของสคริปต์ predict จริงของแต่ละ task ให้ตัดข้อมูลไว้ ณ
เวลาตัดของวันนั้น แล้วเรียก `predict_one_ticker()` ตัวเดิม (โมเดล/feature/พารามิเตอร์ชุดเดียวกับระบบจริง ณ code_commit ที่บันทึกไว้)

| กลุ่ม | ข้อมูลที่ให้โมเดลเห็น | ข้าม guard อะไร |
|---|---|---|
| next_day (task_a, task_c) | ราคาปิดรายวันก่อนวัน target เท่านั้น (จาก `data/task_b_raw_data/` ผ่าน `task_a/verified_daily.py`) | guard ตลาดปิด 10:00-18:00 |
| next_day (task_b) | `raw_data` สำเนา + ข้อมูล Yahoo ถึงวันก่อน target ตัดด้วย `--as-of` ของ task_b เอง | `--as-of` ปกติใช้ได้เฉพาะ dry-run, clean-tree |
| t1600 (task_a2, task_c) | แท่ง 1h ถึง 15:00 ของวัน target (ตัดแท่ง 16:00+ และวันหลังจากนั้น) | guard 16:00-16:30 |
| t1600 (task_b_1600 · รอบ 1) | Yahoo 1h ล่าสุด รวมกับไฟล์ล็อกตามกติกาเดิมของ task_b | บังคับให้ snapshot ดาวน์โหลดวันเดียวกัน ≥16:00 |
| t1600 (task_b_close · รอบ 2) | แท่ง 1h ถึง 15:00 (Yahoo ล่าสุด + ไฟล์ล็อก) + ราคาปิดทางการถึง**วันก่อน** target จาก snapshot จริงใน `task_b/raw_data_daily_live/` | บังคับให้ snapshot ทั้งสองชุดดาวน์โหลดวันเดียวกับ target |

## ไฟล์
- `results/<task>_<mode>.csv` — ผล backfill (schema = log จริงของ task นั้น + `is_backfill`, `backfill_reason`; task_b t1600 มี
  `snapshot_path`, `locked_mismatch_bars`, `historical_x_match` เพิ่ม · `task_b_close_t1600.csv` มี `bar_source`,
  `config_id`, `params`, `target_time` และกลุ่ม `daily_close_*` เพิ่ม = ข้อมูลเดียวกับ sidecar
  `prediction_log_close_meta.csv` ของ log จริง)
  - `backfill_reason`: `missing` = log จริงไม่มีวันนั้นเลย · `partial_models` = log จริงมีแค่ 1 โมเดล/หุ้น (ก่อนเปลี่ยนเป็น 3 โมเดล) backfill เติมครบ 3 โมเดล
- [COVERAGE.md](COVERAGE.md) / `coverage.csv` — ตารางว่าแต่ละวัน/แต่ละชุดมี log จริง, backfill หรือยังขาด
- `validation/` — ผลรัน backfill ในวันที่มี log จริงอยู่แล้ว (เพื่อวัดว่าตรงกับของจริงแค่ไหน) + `validation_vs_live.csv`
- `logs/` — stdout ของทุก run

### ทำไมแท่ง 15:00 ถึงเปลี่ยน และทำไม task_a2 ตรงแค่ 1/6
ทั้ง task_a2 และ task_b อ่าน**แท่งเดียวกัน** (แท่ง label 15:00 ครอบคลุม [15:00,16:00) = ราคา ณ 16:00)
`task_a2` บันทึก `bar_1600_time = 15:00` ทุกแถว ไม่ใช่การใช้แท่งต่างกัน — **Yahoo แก้ค่าแท่งนั้นย้อนหลัง**

วัดจาก log จริงของ task_a2 ทุกวัน (22 ตัวอย่าง = 11 วัน × 2 หุ้น) เทียบกับฉบับที่ Yahoo เก็บไว้ ณ 2026-10-23:

| | จำนวน |
|---|---|
| ค่าไม่เปลี่ยน | 11/22 |
| เปลี่ยน ±1 บาท | 10/22 |
| เปลี่ยน +2 บาท | 1/22 |
| **parity (คู่/คี่) พลิก** | **10/22 (45%)** |

ไม่ใช่แค่เปลี่ยนทีหลัง — เปลี่ยน**ระหว่างรันสดด้วย**: 10-19 ADVANC task_a2 ดึงตอน 16:02:54 ได้ 336 แต่ snapshot
ของ task_b ที่ดึงตอน 16:03:11 (ห่างกัน 17 วินาที) ได้ 335 (ดู `raw_data_intraday_live/20261019/ADVANC_BK_1h_160311.csv`)

ผลกระทบต่างกันตามชนิดของ target:

| ชุด | target | ผลเมื่อ C15 เลื่อน 1 บาท |
|---|---|---|
| task_b_close | **ราคา** (บาท) | ผลเลื่อน ~1 บาท — เสียความแม่นแต่ยังตีความได้ |
| task_c_1600 | ขึ้น/ลงเทียบ C15 | จุดอ้างอิงเลื่อน → label เปลี่ยนได้ (ตรง 4/6) |

สาเหตุที่ต่าง (ยืนยันแล้วว่าไม่ใช่ความสุ่ม — รันซ้ำบนเครื่องนี้ได้ค่าเดิมเป๊ะ):

## ทดสอบ data leak ([leak_test.py](leak_test.py))
คัดลอกข้อมูลที่แคชไว้แล้ว "วางยา" (ราคา ×1.5, volume ×5) แล้วรัน backfill ใหม่แบบออฟไลน์ ผลอยู่ใน `leak_test/leak_test_report.csv`
(รันล่าสุด 2026-10-23 · target 2026-09-29, 2026-10-07, 2026-10-21 · เฉพาะชุดที่ "มีผล backfill ของวันนั้น" ไว้เทียบ
— วันที่ชุดไหนมี log จริงครบอยู่แล้วก็ไม่มีอะไรให้เทียบ ถ้าเอามารวมจะอ่านผลลวงว่า "ไม่เปลี่ยน")
วางยาทั้ง `data/yf_cache/`, `data/task_b_raw_data/` และสำเนา snapshot ราคาปิดรายวันของ task_b
(`raw_data_daily_live/` ผ่าน `BACKFILL_DAILY_LIVE_DIR` · เขียน sha256 ใน meta ใหม่ให้ตรง ไม่งั้น `DC.load_snapshot` ปฏิเสธ)
- **rerun** — ไม่วางยาเลย ใช้วัด "noise ของระบบเอง" เป็นเกณฑ์เทียบของ future (ดูหัวข้อถัดไป — จำเป็น)
- **future** — วางยาเฉพาะข้อมูลที่ไม่ควรเห็น (next_day: ตั้งแต่วัน target ขึ้นไป · t1600: แท่ง 16:00 ของวัน target และทุกอย่าง
  หลังจากนั้น · รอบ 2 เพิ่มราคาปิดทางการตั้งแต่วัน target) -> คำทำนายต้องต่างไม่เกิน noise ของ rerun: **ผ่านครบทุกชุด**
- **control** — วางยาข้อมูลที่ควรเห็น (วันทำการก่อน target / แท่ง 15:00) -> ผลต้องเปลี่ยน: เปลี่ยนครบ ยกเว้น
  `task_c` ของ 2026-10-07 ที่ผลต่าง (1.0) เท่ากับ noise พอดี จึงแยกไม่ออกว่าเปลี่ยนเพราะวางยาหรือเพราะ noise

**รอบ 16:00 ของ 2026-10-21 (3 ชุดที่เพิ่ง backfill) ชัดเจนทั้งหมด**: rerun noise = 0 · future ต่าง 0.000000 ·
control เปลี่ยน (task_a2 166.5 · task_b_close 285.5 · task_c_1600 166.5)

### ข้อควรรู้: XGBoost ของ task_c รันซ้ำแล้วได้ค่าไม่เท่าเดิม (ไม่ใช่ leak)
`task_c/config.py` ตั้ง `XGB_PARAMS` เป็น `n_jobs=-1` + `subsample=0.8` + `colsample_bytree=0.8` ซึ่งกับ
`tree_method="hist"` ทำให้การแบ่งงานต่อ thread เปลี่ยนตามจำนวน thread ที่ได้ตอนรัน -> ผลต่างกันจริง ไม่ใช่แค่ปัดเศษ
วัดกับ target 2026-10-07 (รันด้วย `OMP_NUM_THREADS` ต่างกัน ข้อมูลเดิมทุกอย่าง):

| OMP_NUM_THREADS | 1 | 2 | 4 | 6 | 8 | 12 | ค่าใน `results/` ที่ commit ไว้ |
|---|---|---|---|---|---|---|---|
| KBANK.BK P(ขึ้น) | 0.4662 | 0.4268 | 0.4341 | 0.4090 | 0.4443 | 0.4427 | **0.5179** |
| ADVANC.BK P(ขึ้น) | 0.5826 | 0.5450 | 0.4582 | 0.5460 | 0.5284 | 0.5594 | **0.5823** |

- แถว ANN / Logistic Regression **เหมือนเดิมเป๊ะทุกครั้ง** ต่างแค่ XGBoost · ข้อมูลนำเข้าเหมือนกันหมด
  (`last_close`, `train_rows`, `data_cutoff` ตรงกัน) จึงไม่ใช่การแอบเห็นข้อมูลอนาคต

  **สร้างซ้ำบนเครื่องนี้ไม่ได้** (ตอนนั้น `run_all.py` รัน 6 task ขนานกัน thread ที่ได้จึงต่างจากการรันเดี่ยว)

### ตรวจทั้งโปรเจกต์: ใครยังตั้ง n_jobs=-1 และใครได้รับผลจริง (วัด 2026-10-23)

แต่ผลกระทบต่างกันมากเพราะความแรงของโมเดลและชนิดของ output:

| | task_b รอบ 16:00 | task_c |

LightGBM (task_a/task_a2) ไม่ได้รับผลเลยแม้ตั้ง `n_jobs=-1` → **ต้องแก้แค่ `task_c/config.py` เป็นเรื่องด่วน**
และ `task_b/tune_1600.py` เป็นเรื่องรอง (ผลเล็กแต่ทำให้ regression-check แบบเทียบเป๊ะใช้ไม่ได้)

ข้อควรระวัง: แท่ง 15:00 ถือเป็นข้อมูลที่ "ควรเห็น" เพราะครอบคลุม 15:00-16:00 และราคาปิดทางการเกิดหลังจากนั้น (~16:35)
แต่แท่ง 15:00 ฉบับสุดท้ายต่างจากที่เห็นตอน 16:02 ได้ ±1 tick (ดูหัวข้อความแม่นยำด้านบน) — เทียบ 12 ตัวอย่าง (task_a2 ที่มี log จริง)
ต่างกัน 5 ครั้ง ฉบับสุดท้ายไม่ได้ใกล้ราคาปิดมากกว่าอย่างเป็นระบบ (ค่าเฉลี่ย |ต่างจากราคาปิด| 0.75 vs 0.83 tick) จึงไม่พบหลักฐานว่าแอบเห็นราคาปิด
