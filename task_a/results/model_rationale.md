# เหตุผลที่เลือกโมเดลชุดนี้ (สำหรับใส่รายงาน)

เราเลือกโมเดลเป็นลำดับตามความซับซ้อนที่เพิ่มขึ้น เพื่อให้แต่ละตัวตอบคำถามคนละระดับ:

**Baseline (Majority / Persistence / Markov(1))** ทำหน้าที่จับโครงสร้างพื้นฐานที่สุดของข้อมูล — class imbalance (Majority) และ serial dependence ระดับ 1 อันดับ (Persistence, Markov(1)) โมเดล ML ใดๆ ที่เสนอว่า "ทำนายได้" ต้องเอาชนะจุดเทียบเหล่านี้ก่อน ไม่ใช่แค่เอาชนะการเดาสุ่ม 50/50

**Logistic Regression** เป็นขั้นถัดไป — จับ**สัญญาณเชิงเส้น**ในฟีเจอร์ และให้ coefficient ที่ตีความได้ตรงไปตรงมาว่าฟีเจอร์ไหนมีผลต่อการพลิก parity จริง เหมาะเป็นจุดเทียบ (reference point) ก่อนขยับไปโมเดลที่ซับซ้อนกว่า

**LightGBM** ขยับไปจับ**ความสัมพันธ์แบบไม่เชิงเส้นและ interaction** ระหว่างฟีเจอร์ (เช่น ผลของ volatility ที่อาจขึ้นกับ tick regime ปัจจุบัน) ซึ่ง Logistic Regression จับเองไม่ได้ถ้าไม่ป้อน interaction term ตรงๆ

**ANN (MLP)** เป็นโมเดลที่ยืดหยุ่นที่สุดในชุดนี้ — ทฤษฎีสามารถประมาณค่าฟังก์ชันไม่เชิงเส้นได้แทบทุกรูปแบบ ถ้ามี signal ซ่อนอยู่ในรูปแบบที่ LightGBM มองไม่เห็น ANN ควรมีโอกาสจับได้

**ข้อสรุปที่ได้จากการเรียงโมเดลแบบนี้:** ทุกระดับความซับซ้อน — ตั้งแต่ baseline ที่ง่ายที่สุดไปจนถึง ANN ที่ยืดหยุ่นที่สุด — ให้ผลเสมอกันทางสถิติ (walk-forward OOF accuracy อยู่ในช่วง ~48-52% ทั้งหมด, ไม่มีตัวไหนชนะ baseline อย่างมีนัยสำคัญ) และเมื่อเทียบกับ negative control (ฟีเจอร์สุ่มล้วน) ก็ได้ผลไม่ต่างกัน ในขณะที่ oracle control (ฟีเจอร์ที่ตั้งใจ leak ข้อมูล) กลับถูกตรวจจับได้อย่างชัดเจนและมีนัยสำคัญมาก (AUC ~0.73-0.78)

สิ่งนี้แปลว่า **ปัญหาอยู่ที่ตัวข้อมูลไม่มีสัญญาณให้จับ ไม่ใช่ว่าเราเลือกโมเดลผิดหรือ pipeline มีข้อบกพร่อง** — pipeline พิสูจน์แล้วว่าตรวจจับสัญญาณได้จริงเมื่อมันมีอยู่จริง (oracle control) เพียงแต่ในข้อมูลจริงของ KBANK และ ADVANC ไม่มีสัญญาณแบบนั้นให้พบ
