## 1. ผลหลักต่อโมเดล

ตัวเทียบหลักคือ `pooled` (= แบบที่ `main.py` ทำอยู่ตอนนี้: เทรนทั้ง train ของ fold ครั้งเดียว)

| โมเดล | `pooled` mean MAE_return | ดีที่สุดในกลุ่ม `pretrain_finetune` | ผ่าน guard? | ผ่านกฎตัดสิน? |
|---|---|---|---|---|
| Random Forest | **0.009167** | `warm_start R=500 K=100` 0.009177 (+0.12%) | ผ่าน | **ไม่** |
| XGBoost | **0.009172** | `R=500 K=50 rounds` 0.009207 (+0.39%) | ผ่าน | **ไม่** |
| ANN (MLP) | **0.009199** | `R=500 E=200 lr ×0.1` 0.009157 (−0.46%) | **ไม่ผ่าน** (min StdRatio 0.0254) | **ไม่** |

**กฎตัดสิน** (ประกาศไว้ล่วงหน้า ต้องผ่านครบสามข้อ): (1) mean MAE ต่ำกว่า `pooled`
(2) DM vs `pooled` มีนัยสำคัญ ≥ 4 ใน 6 evaluation (3) `StdRatio ≥ 0.05` ทุก evaluation

### สิ่งที่น่าสนใจที่สุด: ANN "ดีขึ้น" ได้ แต่ด้วยวิธีที่ guard ตั้งใจกัน

ANN มี **3 config ของ `pretrain_finetune` ที่ mean MAE ต่ำกว่า `pooled`** จริง —
และทั้งสามตัว **ตก guard**:

| config | mean MAE_return | vs pooled | min StdRatio | guard |
|---|---|---|---|---|
| `R=500 E=200 lr ×0.1` | 0.009157 | **−0.46%** | 0.0254 | **FAIL** |
| `R=500 E=50 lr ×0.1` | 0.009169 | **−0.33%** | 0.0221 | **FAIL** |
| `R=500 E=50 lr ×1` | 0.009177 | **−0.24%** | 0.0303 | **FAIL** |
| *(เทียบ)* `R=500 E=200 lr ×1` | 0.009363 | +1.78% | 0.0443 | FAIL |

`StdRatio` 0.022–0.030 ของสามตัวแรกแปลว่าคำทำนายแกว่งเพียง
2–3% ของความแกว่งจริง = โมเดล **ยุบเข้าหาค่าคงที่ใกล้ 0** ซึ่งก็คือเข้าใกล้ Naive นั่นเอง
MAE จึงลดลงด้วยเหตุผลเดียวกับที่ Naive ชนะตั้งแต่แรก (ดู `WHY_NAIVE_WINS.md`)
**ไม่ใช่เพราะทำนายเก่งขึ้น**

นี่คือเหตุผลที่ guard ถูกประกาศไว้ล่วงหน้าตั้งแต่ `TUNING_PLAN.md` และยังคงไว้ในรอบนี้:
ถ้าตัดสินด้วย MAE อย่างเดียว เราจะ "ค้นพบ" ว่า fine-tune ช่วย ทั้งที่สิ่งที่เกิดขึ้นคือ
คำตอบเสื่อม (degenerate solution)

## 4. ข้อจำกัดที่ต้องพูดพร้อมผล

1. **RF ไม่ใช่ fine-tune จริง** — RF ปรับน้ำหนักต้นไม้ที่สร้างแล้วไม่ได้ สิ่งที่ทำคือ
   `warm_start=True` เพิ่มต้นไม้ใหม่ K ต้นที่เทรนบน `recent` ต่อจาก 400 ต้นเดิมที่เทรนบน `old`
   → การทำนายเป็น **การผสมแบบถ่วงน้ำหนักคงที่** (`400/(400+K)` : `K/(400+K)`)
   ไม่ใช่การปรับพารามิเตอร์เดิมด้วยข้อมูลใหม่ · ประกาศไว้ตั้งแต่ในแผนและตั้งชื่อ label
   ว่า `warm_start_analogue` เพื่อไม่ให้ใครอ่านผิด
2. **fold ที่ใช้คือ fold ที่ `tune.py` ใช้เลือก Phase 1C มา** → `pooled` มีความเปรียบ
   เล็กน้อยโดยธรรมชาติ (hyperparameter ถูกเลือกมาให้เหมาะกับการเทรนแบบรวมครั้งเดียว
   บน fold เหล่านี้) · การทดลองนี้จึงตอบว่า "fine-tune ชนะ pooled ภายใต้
   hyperparameter ของ pooled ไหม" ไม่ใช่ "fine-tune ที่จูนมาเองจะชนะไหม"
3. **ไม่ได้จูน R / E / K ใหม่** — ทั้งหมดเป็น grid ที่ประกาศไว้ก่อน ไม่ได้ขยายหลังเห็นผล
4. **n เล็ก** — 6 evaluation × 266 แถว · DM test ที่ไม่มีนัยสำคัญ **ไม่ได้แปลว่าเหมือนกัน**
   แปลว่าแยกไม่ออกด้วยข้อมูลเท่านี้
5. **ไม่แตะ test และไม่แตะ fixed val ของ `main.py`** ทั้งหมดอยู่บน walk-forward ของ
   train+val ที่ตัดที่ 2025-02-25 ก่อนสร้าง feature

### หมายเหตุการ implement ที่ guard ของแผนจับได้

`FINETUNE_PLAN.md` ข้อ 6 บังคับให้ตรวจว่าเส้นทาง manual scaling (ที่จำเป็นเพราะ
`partial_fit` ต้องเข้าถึงข้อมูลที่ scale แล้ว) ให้ผลเท่ากับ `Pipeline` +
`TransformedTargetRegressor` ของ `tune.make_model()` ที่ `rtol = 1e-6`

**รอบแรกไม่ผ่าน** — Random Forest บน KBANK fold 3 ได้ manual `0.008376986` vs pipeline
`0.008376856` (ต่าง 1.6e-5) → สคริปต์ HARD STOP ตามแผน ไม่มีไฟล์ผลถูกเขียน

สาเหตุ: `models._scaled` (ANN) มี `StandardScaler` แต่ `models._unscaled` (RF / XGB)
**ไม่มี** · เส้นทาง manual รอบแรก scale X ให้ทุกโมเดล → tree ได้ค่า threshold ต่างกัน
ในระดับ floating point → ต้นไม้คนละต้น · แก้โดยให้ X scaler ทำงานเฉพาะ ANN
(`ScaledFrame.SCALES_X`) แล้วรันใหม่ทั้งหมด → ตรงทุก evaluation (RF ตรงถึง 10 ตำแหน่ง)
รายละเอียดการตัดสินใจอยู่ใน [`DECISIONS.md`](DECISIONS.md) ข้อ 4 · **ไม่ได้แก้ไฟล์แผน**

## 5. เทียบกับผลของ task_a (หลักฐานประกอบ · อ่านอย่างเดียว)

`task_a/results/five_analyses/4_pretrain_finetune.csv` ทำการทดลองแนวเดียวกันบนงาน
**classification** (ทำนายคู่/คี่) ด้วย LightGBM และ ANN · pretrain 2016–2023 →
fine-tune บนปี 2024 · วัดด้วย accuracy บน 400 แถว + McNemar test เทียบ persistence

| | KBANK.BK | ADVANC.BK |
|---|---|---|
| Baseline: Persistence | **0.5175** | **0.4975** |
| LightGBM pretrain only | 0.4900 | 0.4950 |
| LightGBM fine-tune +50 trees | 0.5000 | 0.4750 |
| LightGBM fine-tune +100 trees | 0.4900 | 0.4650 |
| LightGBM fine-tune +200 trees | 0.4825 | 0.4725 |
| LightGBM recent only | 0.5175 | 0.4575 |
| LightGBM pooled | 0.4975 | 0.4925 |
| ANN fine-tune +50 epochs | 0.4975 | 0.5350 |
| ANN pooled | 0.4750 | 0.5350 |

**ข้อสรุปตรงกันสามเรื่อง:**
1. **fine-tune ไม่ช่วย** — ไม่มี arm ใดดีกว่า pooled อย่างมีนัยสำคัญ (McNemar p ต่ำสุด
   ในตารางคือ 0.156 ซึ่งยังไม่ถึง 0.05) เหมือนที่ task_b ได้ DM p ที่ไม่มีนัยสำคัญทุกช่อง
2. **fine-tune นานขึ้น = แย่ลง** — LightGBM +200 trees แย่กว่า +50 trees ทั้งสองหุ้น
   ตรงกับผลของ task_b ที่ `E = 200` แย่กว่า `E = 50` (3/4 คู่) และ `K = 150` แย่กว่า
   `K = 50` (2/2 คู่ของ XGBoost)
3. **ไม่มีอะไรชนะ baseline** — task_a ไม่มี arm ใดชนะ persistence อย่างมีนัยสำคัญ
   task_b ไม่มี arm ใดชนะ Naive อย่างมีนัยสำคัญ

**ข้อต่างที่ต้องระวัง:** task_a เป็น classification วัดด้วย accuracy บน split เดียว 400 แถว
ส่วน task_b เป็น regression วัดด้วย MAE_return บน walk-forward 6 evaluation × 266 แถว
→ เทียบกันได้ในระดับ "ทิศทางของข้อสรุป" เท่านั้น ไม่ใช่ตัวเลขต่อตัวเลข

## 6. สิ่งที่ยังไม่ได้ทำ / งานต่อ

- ไม่ได้ลอง **จูน hyperparameter แยกสำหรับขั้น fine-tune** (เช่น ANN ที่ capacity ใหญ่ขึ้น
  ตอน pretrain แล้วลดตอน fine-tune) — เพิ่ม search space และเสี่ยง overfit ต่อ fold
- ไม่ได้ลอง **R ที่ใหญ่กว่า 500** หรือ fine-tune แบบหลายขั้น (old → mid → recent)
- ไม่ได้ลอง **early stopping ตอน fine-tune** โดยใช้ส่วนท้ายของ `recent` เป็น holdout
  (จะเพิ่ม hyperparameter และตัดข้อมูลที่มีน้อยอยู่แล้วให้น้อยลงอีก)
- RF ยังไม่มีวิธีทำ fine-tune จริง — ถ้าต้องการ ต้องเปลี่ยนไปใช้โมเดลที่ปรับน้ำหนักได้

## 7. ย้ำ: ไม่ได้นำผลนี้ไปใช้กับโมเดลจริง

`config.py` **ไม่ถูกแก้** จากการทดลองนี้ (`ANN_PARAMS` / `RF_PARAMS` / `XGB_PARAMS` /
`RECENCY_HALF_LIFE` / `CONFIG_TAG` เหมือนเดิมทุกค่า) · `weighting.py` ยังเป็นวิธีที่ใช้จริง
(และยังปิดอยู่เพราะ half-life = None ชนะ) · สคริปต์ live ไม่ถูกแตะ

ผลรอบนี้เป็น **หลักฐานว่าเหตุผลที่ `weighting.py` เขียนไว้ตั้งแต่แรกนั้นถูกต้อง** —
วิธี 2 ขั้นเพิ่ม hyperparameter (R, E/K, lr) และเสี่ยงให้โมเดลยุบเข้าหาค่าคงที่
โดยไม่ได้อะไรกลับมา — ตอนนี้มีตัวเลขยืนยันแล้ว ไม่ใช่แค่เหตุผลเชิงทฤษฎี
