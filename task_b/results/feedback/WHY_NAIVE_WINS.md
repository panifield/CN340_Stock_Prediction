## สรุป 1 ย่อหน้า (ใช้พูดได้เลย)

MAE ลงโทษทุกบาทที่ทายผิดเท่ากัน และราคาปิด **ไม่ขยับเลยประมาณ 15% ของวัน** ในวันเหล่านั้น
Naive ที่ทาย "return = 0" มี error **= 0 เป๊ะ** ซึ่งเป็นเพดานล่างที่โมเดลเอาชนะไม่ได้ ได้แค่เสมอ
ส่วนโมเดล ML ที่ทายค่าไม่เป็นศูนย์ เสีย error ทุกวันนิ่งแบบหนีไม่ได้ (ดูข้อ 2) ·
ภายใต้ **absolute loss (MAE)** ซึ่งเป็น primary metric ของงาน B ส่วนต่างระหว่างโมเดลกับ Naive
**แยกจาก 0 ไม่ได้เลยทั้ง 18 evaluation** ไม่ว่าจะทดสอบว่าโมเดลดีกว่าหรือ Naive ดีกว่า
(DM test, α = 0.05 one-sided) · แต่ภายใต้ **squared loss (MSE)** ซึ่งลงโทษ error ก้อนใหญ่
หนักกว่า โมเดลมี loss ต่ำกว่า Naive ใน **16/18 evaluation** และมีนัยสำคัญก่อนปรับหลาย
การทดสอบใน **3/18** (ทั้งสามช่องเป็นหุ้น ADVANC) แต่ **ไม่เหลือสักช่องหลัง Bonferroni
correction** (α/6 = 0.00833) — ดูตัวเลขเต็มที่ข้อ 5
-> ข้อสรุปที่ถูกต้องไม่ใช่ "Naive เหนือกว่า ML" ตายตัว แต่คือ **"สัญญาณที่หาได้จากราคาย้อนหลัง
มีอยู่จริงแต่อ่อนมาก และการเลือก loss function เปลี่ยนว่าใครดูดีกว่า"** ซึ่งยังสอดคล้องกับ
efficient market hypothesis (R1) ที่บอกว่าไม่ควรมีสัญญาณที่แข็งพอให้ทำกำไรได้จากราคาในอดีต
เพียงอย่างเดียว

## 2. การแยก MAE: Naive ได้เปรียบจากวันนิ่งเท่าไหร่

`stats_tests.mae_decomposition()` แยกส่วนต่าง MAE เป็นสองพจน์ที่รวมกันได้ค่าเดิมเป๊ะ:

```
mae_model − mae_naive  =  contrib_zero_days  +  contrib_moved_days
                          (วันที่ y = 0)       (วันที่ y ≠ 0)
```

**บน fixed val** (`results/<TICKER>_taskB_val_stats.csv`)

| หุ้น | โมเดล | relMAE | เสียเปรียบจากวันนิ่ง | ได้เปรียบจากวันขยับ | รวม |
|---|---|---|---|---|---|
| KBANK | Random Forest | 1.0019 | +0.000135 | −0.000119 | +0.000015 |
| KBANK | XGBoost | 1.0033 | +0.000079 | −0.000052 | +0.000027 |
| KBANK | ANN (MLP) | 1.0106 | +0.000141 | −0.000052 | +0.000088 |
| ADVANC | XGBoost | **0.9983** | +0.000125 | −0.000141 | **−0.000016** |
| ADVANC | ANN (MLP) | **0.9993** | +0.000147 | −0.000154 | **−0.000007** |
| ADVANC | Random Forest | 1.0017 | +0.000159 | −0.000144 | +0.000016 |

**บน walk-forward 18 evaluation** (`walkforward_summary.csv`)

| โมเดล | mean relMAE | เสียเปรียบจากวันนิ่ง (เฉลี่ย) | ได้เปรียบจากวันขยับ (เฉลี่ย) |
|---|---|---|---|
| Random Forest | 1.0025 | +0.000140 | −0.000120 |
| XGBoost | 1.0029 | +0.000097 | −0.000072 |
| ANN (MLP) | 1.0061 | +0.000154 | −0.000100 |

**อ่านอย่างไร**
- `contrib_zero_days` **บวกทุกช่อง ไม่มีข้อยกเว้น** — เพราะ Naive มี error = 0 บนวันนิ่งเสมอ
  (`mae_naive_zero_days = 0.0` ทุกแถวในทุกไฟล์) โมเดลจึงเสียเปรียบตรงนี้แบบหนีไม่ได้
- `contrib_moved_days` **ติดลบ 16 จาก 18 evaluation** — เมื่อ MAE รวมใกล้เคียง Naive
  (relMAE ~1.00) พจน์นี้**เกือบต้องติดลบตามบัญชี** เพื่อหักล้าง `contrib_zero_days` ที่เป็นบวก
  เสมอ จึง **ไม่ใช่หลักฐานของฝีมือโดยตัวมันเอง** — ตัวอย่าง ADVANC fold 3: XGBoost MAE บน
  วันขยับ 0.011952 vs Naive 0.012133 (`mae_model_moved_days` / `mae_naive_moved_days`)
  และการแบ่งวันตามค่า `y` จริงใช้ตอนทำนายไม่ได้ เพราะไม่รู้ล่วงหน้าว่าวันไหนราคาจะนิ่ง
  — เป็นการแยกส่วนทางบัญชีของ error ที่เกิดขึ้นแล้ว ไม่ใช่กลยุทธ์ที่ทำได้จริง
- หลักฐานของสัญญาณอ่อน ๆ ที่พอใช้ได้จริงคือ **IC ที่เป็นบวก 16/18 evaluation** (ข้อ 4)
  และผล **DM ภายใต้ MSE** (ข้อ 5) — ไม่ใช่การแยกส่วน MAE นี้

> **ประโยคสำหรับสไลด์:** ภายใต้ MAE โมเดลแยกจาก Naive ไม่ออก ภายใต้ MSE โมเดลดีกว่าเกือบ
> ทุก fold แต่ยังไม่มีนัยสำคัญหลังแก้การทดสอบหลายครั้ง — สัญญาณจากราคาย้อนหลังมีอยู่แต่อ่อนมาก
> และ metric ที่เลือกเปลี่ยนว่าใครดูดีกว่า

ก็สั่งซื้อขายตามไม่ได้

## 5. DM test: ต่างจาก Naive อย่างมีนัยสำคัญไหม → ขึ้นอยู่กับ loss function

Diebold–Mariano + HLN small-sample correction เทียบกับ t-distribution df = n − 1 ·
α = 0.05 one-sided (H1: โมเดล loss ต่ำกว่า Naive) · รายงานทั้งสอง loss เพราะให้ภาพต่างกัน:
**absolute loss (MAE)** คือ primary metric ของงาน B (ใช้เลือกโมเดล) ส่วน **squared loss
(MSE)** ลงโทษ error ก้อนใหญ่หนักกว่า จึงไวต่อสัญญาณที่ปรากฏเป็นครั้งคราวในวันที่ราคาขยับแรง
(ดูคำอธิบายว่าทำไมสองค่าต่างกันท้ายข้อนี้)

### Absolute loss (MAE)

**walk-forward 6 evaluation ต่อโมเดล** (`walkforward_summary.csv` / `walkforward_stats.csv` คอลัมน์ `dm_abs_*`)

| โมเดล | evals ที่ MAE ต่ำกว่า Naive | ชนะอย่างมีนัยสำคัญ (α = 0.05) | หลัง Bonferroni (α = 0.00833) | **แพ้** อย่างมีนัยสำคัญ | p one-sided ที่เล็กสุด |
|---|---|---|---|---|---|
| ANN (MLP) | 1 / 6 | **0 / 6** | **0 / 6** | 0 / 6 | 0.433 |
| Random Forest | 2 / 6 | **0 / 6** | **0 / 6** | 0 / 6 | 0.410 |
| XGBoost | 2 / 6 | **0 / 6** | **0 / 6** | 0 / 6 | 0.233 |
| **รวม** | **5 / 18** | **0 / 18** | **0 / 18** | **0 / 18** | |

Bonferroni: α / 6 evaluation = 0.05 / 6 = **0.008333**

**fixed val, absolute loss** (`results/<TICKER>_taskB_val_stats.csv` คอลัมน์ `dm_abs_*`)

| หุ้น | โมเดล | DM (HLN) | p one-sided | p two-sided | สรุป |
|---|---|---|---|---|---|
| ADVANC | XGBoost | −0.240 | 0.405 | 0.811 | MAE ต่ำกว่า Naive แต่ **ไม่มีนัยสำคัญ** |
| ADVANC | ANN (MLP) | −0.123 | 0.451 | 0.902 | MAE ต่ำกว่า Naive แต่ **ไม่มีนัยสำคัญ** |
| ADVANC | Random Forest | +0.210 | 0.583 | 0.834 | แพ้ Naive ไม่มีนัยสำคัญ |
| KBANK | Random Forest | +0.280 | 0.610 | 0.780 | แพ้ Naive ไม่มีนัยสำคัญ |
| KBANK | XGBoost | +0.730 | 0.767 | 0.466 | แพ้ Naive ไม่มีนัยสำคัญ |
| KBANK | ANN (MLP) | +1.511 | 0.934 | 0.132 | แพ้ Naive ไม่มีนัยสำคัญ |

**สรุป absolute loss:** จาก 18 evaluation walk-forward + 6 แถวบน fixed val
**ไม่มีสักช่องเดียว** ที่ส่วนต่าง MAE ระหว่างโมเดลกับ Naive แยกจาก 0 ได้ที่ α = 0.05
(ทั้งสองทิศ) → `n_sig_better_uncorrected = 0` และ `n_sig_worse_uncorrected = 0` ทุกโมเดล

3/18 evaluation ที่มีนัยสำคัญก่อนปรับหลายการทดสอบ — **แต่ไม่เหลือสักช่องหลัง Bonferroni**
และผลที่มีนัยสำคัญกระจุกอยู่ที่หุ้น ADVANC เท่านั้น (ไม่มีช่องของ KBANK ที่ p < 0.05)

### ตีความรวม: ทำไมสอง loss ให้ผลต่างกัน

MSE ลงโทษ error ก้อนใหญ่หนักกว่า MAE (ยกกำลังสอง vs ค่าสัมบูรณ์) โมเดลที่ shrink เข้าหา 0
(ดูข้อ 3) แต่ขยับไปทางที่ถูกเล็กน้อยในวันที่ราคาขยับแรง จะลด error ก้อนใหญ่ของ Naive
(ซึ่งทาย 0 เสมอ ไม่เคยปรับตามขนาดการขยับ) ได้ในแบบที่ MSE จับ แต่ MAE มองไม่เห็น —
MAE ให้น้ำหนักทุกวัน (รวมวันนิ่งที่ Naive ถูกเป๊ะ) เท่ากันหมด ไม่สนใจว่า error วันไหนใหญ่กว่า
**ผลคือการเลือก metric มีผลต่อข้อสรุปจริง** ซึ่งสอดคล้องกับที่งาน 16:00 เคยเห็น R²_OOS
เป็นบวกทั้งที่ MAE ไม่ชนะ (`INTRADAY_FINDINGS.md`)

**ข้อควรระวัง:** ผลที่มีนัยสำคัญ (ก่อนแก้หลายการทดสอบ) กระจุกอยู่ที่หุ้น ADVANC ทั้งสามช่อง —
เมื่อทดสอบ 6 evaluation ต่อโมเดลโดยไม่ปรับค่า ก็มีโอกาสพบผลบวกปลอมได้โดยบังเอิญอยู่แล้ว
**ห้ามสรุปว่าโมเดลใช้ได้กับ ADVANC โดยเฉพาะ** จากตัวเลขชุดนี้ · n เล็กและหลาย evaluation
ทำให้ผลเดี่ยว ๆ ที่ดูมีนัยสำคัญอาจเป็นความบังเอิญ (ดูข้อ 7)

ค่า `Baseline: Mean Return` ใช้ตรวจความไวของเครื่องมือได้ **บางส่วนเท่านั้น** (รายละเอียด
ว่าทำไมไม่พิสูจน์ความไวต่อขนาดผลเล็ก ๆ ดูข้อ 7): ภายใต้ MAE มันแพ้ Naive อย่างมีนัยสำคัญ
ทั้งสองหุ้น (KBANK p two-sided = 0.00048 · ADVANC p two-sided = 0.0084) แต่ภายใต้ MSE
กลับ**ไม่มีนัยสำคัญ** (KBANK 0.832, ADVANC 0.175)

## 6. เชื่อมกับ efficient market hypothesis

Naive baseline ของเรา (`baselines.baseline_naive_return` → ทำนาย return = 0)
**คือ random walk แบบตรงตัว** · EMH แบบ weak form (Fama 1970 — R1 ใน
`../../REFERENCES.md`) บอกว่าราคาในอดีตเพียงอย่างเดียวไม่ควรทำนายราคาในอนาคตได้
พอจะทำกำไรหลังหักต้นทุน

สิ่งที่เราวัดได้สอดคล้องกับนั้นพอดี และยัง **ละเอียดกว่าคำว่า "ทำนายไม่ได้"**:
1. มีสัญญาณอยู่จริง (IC เป็นบวก 16/18 evaluation, hit rate เฉลี่ย 54–55% บนวันที่ราคาขยับ)
2. ขนาดของสัญญาณขึ้นกับ loss function ที่ใช้วัด: ภายใต้ **absolute loss (MAE)** เล็กเกินกว่า
   จะแยกจาก Naive ได้อย่างมีนัยสำคัญเลย (DM test 0/18) ส่วนภายใต้ **squared loss (MSE)**
   มีนัยสำคัญก่อนปรับหลายการทดสอบใน 3/18 evaluation (ทั้งหมดเป็นหุ้น ADVANC) แต่ไม่เหลือ
   หลัง Bonferroni correction → สัญญาณที่มีอยู่ยังเล็กและไม่สม่ำเสมอพอจะยืนยันได้แน่นอน
3. และเล็กกว่าต้นทุนการซื้อขาย: `mean_pred_move_ticks` 0.14–0.24 tick ขณะที่ต้นทุนไป-กลับ
   = **33.598 bps** และโมเดลแนะนำให้ซื้อเพียง **0–1.9% ของวัน** ที่อัตราค่าคอมมิชชันปัจจุบัน
   (`results/<TICKER>_taskB_val_costs.csv` → `pct_pred_above_cost`) ·
   ถ้าลดค่าคอมมิชชันเป็น 0.10% (ต่ำสุดที่ตรวจเจอ) ตัวเลขนี้ขึ้นเป็นเพียง 1.4–3.9%
   (`results/cost_sensitivity.csv`) → **ข้อสรุปไม่เปลี่ยนเมื่อค่าธรรมเนียมเปลี่ยน**

## 7. ข้อจำกัด (ต้องพูดด้วย)

1. **val ถูกใช้จูนมาแล้ว** — `TUNING_PLAN.md` fold 2–3 ของ `tune.py` ทับช่วง validation
   ของ `main.py` · ตัวเลขบน fixed val (362 แถว) จึงเป็น in-sample ของการเลือก
   hyperparameter **ไม่ใช่การประเมินอิสระ** และมองในแง่ดีเกินจริง
2. **walk-forward 6 evaluation ก็ไม่อิสระ** — เป็น fold ชุดเดียวกับที่ `tune.py` ใช้เลือก
   config Phase 1C มา ตัวเลขในข้อ 5 จึงเป็น "ผลของผู้ชนะบนสนามที่มันถูกเลือกมา"
3. **n เล็ก และอำนาจการทดสอบ (power) ไม่ชัดเจน** — แต่ละ evaluation มี 266 แถว · HLN
   correction ช่วยให้ conservative ขึ้น (ทำให้ p ใหญ่กว่าการใช้ normal distribution) แต่
   ไม่ได้แก้ปัญหาอำนาจการทดสอบ: ส่วนต่างระดับ 1e-5 บน 266 วันตรวจจับไม่ได้ ไม่ว่าจะมีจริง
   หรือไม่ · **กรณี `Baseline: Mean Return` ไม่ได้พิสูจน์ว่าการทดสอบไวพอจะจับความได้เปรียบ
   ขนาดเล็กของโมเดล ML** — นัยสำคัญของ DM test ขึ้นกับ**ความแปรปรวนของส่วนต่าง loss รายวัน**
   ไม่ใช่ขนาดของส่วนต่างเฉลี่ย: Mean Return ทายค่าคงที่ทุกวัน ส่วนต่าง loss ของมันจึงแกว่ง
   น้อยมาก (ตรวจจับง่าย แม้ relMAE ใกล้ 1.00 มาก — KBANK 1.0009, p two-sided = 0.0005)
   ขณะที่โมเดล ML ทายต่างกันทุกวัน ส่วนต่าง loss จึงแกว่งมากกว่า (ตัวอย่าง KBANK Random
   Forest relMAE 1.0019 ซึ่งห่างจาก Naive มากกว่า Mean Return แต่ p two-sided = 0.78)
   → นัยสำคัญของ Mean Return ไม่ได้แปลว่า DM test ไวพอจะจับโมเดล ML ที่มีความได้เปรียบ
   เล็กแต่สม่ำเสมอแบบเดียวกัน
4. **DM test สมมติ loss differential เป็น stationary** · return รายวันมี volatility clustering
   ซึ่งกระทบ variance ที่ประมาณได้ (h = 1 จึงไม่มีพจน์ autocovariance มาช่วย)
5. **historical test ยังไม่ถูกเปิด** — ไม่มี `PRE_TEST_LOCK.md` ในโปรเจกต์ ตัวเลขทั้งหมด
   ในไฟล์นี้เป็น train/val เท่านั้น การเปิด test เป็นการตัดสินใจของผู้ใช้
6. ตัวเลขทั้งหมดในไฟล์นี้ **ไม่ถูกใช้เลือกอะไรเลย** — การเลือกโมเดลใช้ `MAE_return` เท่านั้น
