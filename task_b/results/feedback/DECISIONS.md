## 4. 2026-10-24 · X scaler ใน `finetune_experiment.py` ต้องตามโมเดล ไม่ใช่ทุกโมเดล

**เรื่อง**
`FINETUNE_PLAN.md` ข้อ 1 เขียนว่า "StandardScaler ของ X และของ y fit จาก train ทั้ง fold
ครั้งเดียว" และข้อ 6 ให้ตรวจว่าเส้นทาง manual scaling ให้ผลเท่ากับ
`Pipeline` + `TransformedTargetRegressor` ของ `tune.make_model()` ที่ `rtol = 1e-6`

รอบแรกที่รัน guard ข้อ 6 **จับได้จริง**: Random Forest บน KBANK fold 3 ได้
manual `0.008376986047547995` vs pipeline `0.008376855641912751` (ต่าง 1.6e-5 > rtol)
จึง HARD STOP ตามแผน ไม่มีไฟล์ผลถูกเขียน

**สาเหตุ**
`models._scaled` (ANN) = `Pipeline(impute, StandardScaler, model)` แต่
`models._unscaled` (RF / XGB) = `Pipeline(impute, model)` — **ไม่มี StandardScaler เลย**
เส้นทาง manual รอบแรก scale X ให้ทุกโมเดล → tree ได้ค่า X คนละชุดกับ pipeline เดิม
tree ไม่สนใจ scale ในเชิงทฤษฎี (การแบ่งเป็น monotone transform) แต่ค่า threshold ที่
คำนวณได้ต่างกันในระดับ floating point → ต้นไม้คนละต้น → MAE ต่างราว 1e-5

**ทางเลือก**
- (ก) ให้ X scaler ทำงานเฉพาะโมเดลที่ pipeline เดิม scale (ANN) ส่วน tree ใช้ X ดิบ
- (ข) ผ่อน `rtol` ให้หลวมพอที่ความต่างนี้ผ่าน

**เลือก: (ก)** — `ScaledFrame.SCALES_X = {"ANN (MLP)"}` และ `ScaledFrame.X()`
รับชื่อโมเดลเป็นพารามิเตอร์

**เพราะอะไร**
- (ข) คือการแก้เกณฑ์ตรวจหลังเห็นผล ซึ่งเป็นสิ่งที่กติกาของโปรเจกต์นี้ห้ามทั่วทั้ง repo
- (ก) ทำให้ arm `pooled` **เทียบเท่า pipeline ของจริง** ซึ่งเป็นเจตนาของข้อ 6 ตรง ๆ
  (ตัวเทียบหลักต้องเป็น "แบบปัจจุบัน" จริง ไม่ใช่ของที่ใกล้เคียง)
- y scaler ยังใช้กับทุกโมเดล เพราะ `main.py` / `tune.py` ห่อทุกตัวด้วย
  `TransformedTargetRegressor(StandardScaler())` อยู่แล้ว

**ไม่ได้แก้ `FINETUNE_PLAN.md`** (SHA-256 ล็อกไว้แล้ว) — ข้อ 1 ของแผนยังเป็นจริงทุกคำ
สิ่งที่เปลี่ยนคือ *ที่ใด* ที่ X scaler ถูกใช้ ให้ตรงกับ pipeline เดิม ซึ่งเป็นสิ่งที่
ข้อ 6 ของแผนเรียกร้องอยู่แล้ว · บันทึกไว้ใน `FINETUNE_RESULTS.md` ด้วย

## 8. 2026-10-24 · ผลตรวจ leakage โดย subagent + สิ่งที่แก้ตาม

**เรื่อง**
ข้อ 7 ของงานรอบนี้ให้ใช้ subagent ที่ไม่เห็นงานมาก่อน ตรวจ leakage ของ
`features_experimental.py`, `finetune_experiment.py`, `optuna_features.py`
(fold boundary, shift, scaler, ข้อมูลหลัง 2025-02-25)

**ผล: ไม่พบ leakage ที่ยืนยันได้แม้แต่ข้อเดียว**
สิ่งที่ผู้ตรวจยืนยันด้วยการทดลองจริง (ไม่ใช่แค่อ่านโค้ด):
- **วางยาข้อมูลหลัง val_end** (คูณ OHLC 7 เท่า, volume 13 เท่า, เพิ่มแถวปี 2026-11)
  -> `load_dev_data_grouped` และ `tune.load_dev_data` คืน X, y และ fold index
  **เหมือนเดิมทุกบิต**
- **วางยา y ของแถว eval** และวางยา X+y ของทุกแถวหลัง eval window
  -> คำทำนายของ `eval_task_pred`, `predict_pooled`, `predict_xgb_finetune`,
  `predict_rf_warmstart` **เหมือนเดิมทุกบิต**
- **ตรวจ cross_stock ทุกเซลล์** (8,280 เซลล์ต่อหุ้น) -> ตรงกับ indicator ของหุ้นคู่
  ณ วันซื้อขาย**ก่อนหน้า** 100% และไม่มีเซลล์ใดเท่ากับค่าวันเดียวกัน
- scaler ของทุก fold fit จาก train เท่านั้น (ตรงกับ `StandardScaler` ที่ fit บน
  `X_tr`/`y_tr` เป๊ะ · ต่างจากที่ fit ทั้ง dataset)
- Optuna เห็น fold 1-2 เท่านั้น (fold 3 ไม่ตัดกับ train/eval ที่ใช้ค้นเลย · ไม่มี pruner
  · ไม่เคยเรียก `trial.report`)
- null test สลับ y ของ train เท่านั้น (`y_ev` ไม่เคยถูกเขียนทับ)

**สิ่งที่ผู้ตรวจชี้ว่าควรแก้ (ไม่ใช่ leak แต่เป็นความเปราะ) และแก้แล้วรอบนี้**

1. **`verify_no_leak_experimental` ส่ง `X_all` เข้า `features.verify_no_leak` ตรง ๆ**
   ฟังก์ชันนั้นเทียบ feature แถว `i` กับ raw แถว `i-1` **ตามตำแหน่ง** แต่ `X_all`
   ผ่าน inner join มาแล้ว -> ตำแหน่งตรงกับ `df` เฉพาะตอนที่ปฏิทินสองหุ้นเหมือนกันทุกวัน
   ผู้ตรวจจำลองให้หุ้นคู่ขาด 3 วัน แล้ว**การตรวจล้มด้วยเหตุผลที่ผิด** (false alarm)
