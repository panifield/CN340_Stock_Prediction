## 2. ข้อจำกัด 4 ข้อ

### (1) ไม่มีข้อมูลในช่วง train ของโมเดลรายวันเลย

| partition ตาม `SPLIT_BY_DATE` ของโมเดลรายวัน | จำนวนวัน |
|---|---|
| TRAIN (≤ 2023-09-01) | **0** |
| VAL (2023-09-04 → 2025-02-25) | 341 |
| TEST (2025-02-26 → 2026-08-28) | 361 |
| หลังขอบ daily data (> 2026-08-28) | 20 |
| **รวม** | **722** |

→ ใช้ `SPLIT_BY_DATE` เดิมกับโมเดล 16:00 ไม่ได้ และห้ามแก้ `SPLIT_BY_DATE` · การประเมินใช้โครงในข้อ 4

### (2) คนละแหล่งกับข้อมูลรายวัน และตัวเลขไม่ตรงกัน

ราคาปิดแท่ง 16:00 (Yahoo) เทียบกับราคาปิดรายวันใน `raw_data/` (investing.com) บน 701 วันที่ทับกัน:

| | ตรงกันเป๊ะ | mean \|ต่าง\| | max \|ต่าง\| |
|---|---|---|---|
| KBANK | 45.6% | **0.33 บาท** | 2.00 บาท |
| ADVANC | 40.5% | **0.69 บาท** | 3.00 บาท |

ช่องว่างระหว่างโมเดลกับ naive ของโปรเจกต์นี้ = 1.9–3.2 สตางค์/วัน → ความไม่ตรงกันของสองแหล่ง
ใหญ่กว่าราว 17–22 เท่า

**กฎ:** ห้ามผสม feature จาก Yahoo กับ target จาก investing.com (หรือกลับกัน) ในโมเดลเดียว

### (3) ความหมายของ timestamp และ target ยังไม่ได้ยืนยัน

SET ซื้อขายต่อเนื่องถึง 16:30 แล้วเข้า closing auction ซึ่งปิดจริงราว 16:35–16:40
→ ถ้าออกคำทำนาย ณ 16:00 ข้อมูลหลัง 16:00 ยังไม่เกิด

สมมติฐาน (ยังไม่ได้ยืนยัน): timestamp คือ "เวลาเริ่ม" ของช่วงชั่วโมง

```
แท่ง 15:00  = 15:00 -> 16:00   = รู้แล้ว ณ 16:00        ใช้เป็น feature ได้
แท่ง 16:00  = 16:00 -> ปิดตลาด = ยังไม่เกิด ณ 16:00     ห้ามอ่านเป็น feature
```

- ห้าม feature ใดอ่านค่าจากแท่ง 16:00 (ทั้ง O/H/L/C/V) · ถ้าได้ R² สูงผิดปกติ ให้สงสัยข้อนี้ก่อน
- ราคาปิดแท่ง 16:00 เรียกว่า **`close_bar16`** ไม่ใช่ "ราคาปิดทางการ"
- **สถานะการยืนยัน: ยังไม่ได้ยืนยัน** — ต้องมีไฟล์ราคาปิดรายวันจาก Yahoo (interval `1d`)
  แล้วรัน `python tools/intraday_probe.py --yahoo-daily <ไฟล์>`

### (4) ข้อมูลไม่สะอาด

- วันที่ไม่มีแท่ง 15:00 หรือ 16:00 (2025-03-28, 2026-04-20) → ตัดทิ้งทั้งวัน ห้าม forward-fill
- แท่ง 10:00 มี `Volume = 0` ใน 72–76% ของวัน → ห้ามสร้าง feature ปริมาณซื้อขายจากแท่งนี้
- แท่ง 13:00 ไม่สม่ำเสมอ → ห้ามใช้เป็น feature ที่บังคับต้องมี
- 2 วันที่มีใน daily แต่ไม่มีใน hourly → เป็น missing ไม่ใช่ ffill
- **(เพิ่ม 2026-09-27)** ADVANC **2025-09-16 ไม่มีแท่ง 14:00** — ตารางข้อ 1 ตรวจแค่แท่ง 15/16 จึงไม่เห็น
  เมื่อใช้เกณฑ์ของ Phase 1D (ต้องมีแท่ง 10, 11, 12, 14, 15, 16) จะได้ eligible days
  KBANK 720 · ADVANC **719** (ดู `PHASE1D_PLAN.md` ข้อ 3)

## 3. "Predict ตอน 16:00" ตีความได้หลายแบบ

| แนว | ความหมาย | เป็นโมเดลใหม่ไหม |
|---|---|---|
| **A** | ณ 16:00 ทำนาย `close_bar16` ของวันเดียวกัน | ใหม่ (horizon ~30–40 นาที) |
| **B1** | รันโมเดลรายวันเดิม (ข้อมูลถึง t−1) ให้เสร็จก่อน 16:00 | ไม่ใหม่ — เปลี่ยนแค่เวลารัน |
| **B2** | ณ 16:00 วันนี้ ทำนายราคาปิดพรุ่งนี้ โดยใช้ข้อมูล intraday ของวันนี้ถึง 16:00 ด้วย | ใหม่จริง — feature set ใหม่ |

ความยากของโจทย์ วัดภายในแหล่งเดียว (Yahoo) · naive = ทาย "ไม่เปลี่ยนจากราคา ณ แท่ง 15:00"
· ต้นทุนไป-กลับ = 0.336% จาก `cost_round_trip()`:

| | n | naive MAE | std | ไม่ขยับเลย | naive MAE ÷ ต้นทุน | \|ขยับ\| เกินต้นทุน (magnitude) | ขึ้นเกินต้นทุน (long-only) |
|---|---|---|---|---|---|---|---|
| **A** KBANK | 720 | 0.198% | 0.297% | 48.9% | 0.59x | 26.7% | 16.0% |
| **A** ADVANC | 720 | 0.248% | 0.356% | 43.3% | 0.74x | 41.5% | 22.4% |
| **B2** KBANK | 718 | 0.873% | 1.198% | — | 2.60x | 73.1% | 41.5% |
| **B2** ADVANC | 718 | 0.977% | 1.348% | — | 2.91x | 77.7% | 41.1% |
| *อ้างอิง: รายวัน ปิด→ปิด (Yahoo)* KBANK | 719 | 0.866% | 1.200% | — | 2.58x | 73.7% | 40.3% |
| *อ้างอิง: รายวัน ปิด→ปิด (Yahoo)* ADVANC | 719 | 0.984% | 1.346% | — | 2.93x | 80.4% | 41.4% |

นิยามที่ใช้: B2 = `close_bar16(t+1) / close_bar15(t) − 1` โดย t+1 = วันทำการถัดไปในไฟล์
และตัดคู่ที่ขาดแท่งทิ้ง (ไม่จับคู่คร่อมวันที่ถูกตัด → horizon 1 วันจริงทุกคู่)

**สิ่งที่ตัวเลขบอก (ไม่ overclaim):**

- **แนว A:** โดยเฉลี่ยความเคลื่อนไหวที่เหลือหลังแท่ง 15:00 **เล็กกว่าต้นทุนไป-กลับ**
  (0.59x / 0.74x) แต่ยังมี 26.7% / 41.5% ของวันที่ขนาดการขยับเกินต้นทุน และถ้านับเฉพาะ
  ขาขึ้น (ที่ long/cash ใช้ได้จริง) เหลือ 16.0% / 22.4% → ต้องประเมินความคุ้มค่า
  **รายสัญญาณ** ไม่ใช่สรุปว่าเป็นไปไม่ได้ทั้งหมด
- เพราะ horizon สั้นกว่ามาก **MAE / R² ของแนว A จะดูดีกว่าโมเดลรายวันมากโดยไม่ได้แปลว่าเก่งขึ้น**
  (กับดักแบบเดียวกับ R²_price) → เทียบกับ naive ของแนว A เท่านั้น ห้ามวางตัวเลขข้ามโจทย์ในตารางเดียวกัน
- **แนว B2:** naive ยากพอ ๆ กับโจทย์รายวันเดิม (std 1.198% vs 1.200%) → โจทย์ไม่ได้ง่ายลง
  แต่โมเดลได้ข้อมูลของวันนี้ถึง 16:00 เพิ่ม → วัดได้ตรง ๆ ว่า "ข้อมูล intraday ช่วยไหม"

## 4. การประเมินโมเดล 16:00 — ไม่มี historical test

ข้อมูลทั้ง 722 วัน **ถูกเปิดดูไปแล้ว** ในการสำรวจนี้ → ช่วงไหนก็เรียกว่า "test ที่ไม่เคยเห็น" ไม่ได้
ห้ามตัดช่วงท้าย (เช่น 2026-04 → 2026-09) มาเรียกว่า test

```
2023-10-02 -> 2026-09-25  (722 วัน) = development dataset ทั้งหมด
        |
        v
chronological walk-forward CV ภายใน 722 วัน   <- ติดป้าย "development / walk-forward" ห้ามเรียก test
        |
        v
freeze pipeline + commit + CONFIG_TAG
        |
        v
prospective test ตั้งแต่วันซื้อขายแรกหลัง freeze (>= 2026-09-28) = live test ของอาจารย์
```

## 6. Design ที่เตรียมไว้สำหรับ Phase 1D (ร่างเดิมของ Phase 1C)

> ร่างนี้ถูกแทนที่ด้วยแผนที่ล็อกใน `PHASE1D_PLAN.md` (Mode A: 21 features, แท่ง 13 ไม่อ่านเลย ฯลฯ)
> ถ้าขัดกัน ให้ถือ `PHASE1D_PLAN.md`

```
ร่วมกันทั้ง A และ B2
  แหล่งข้อมูล       : ไฟล์ Yahoo รายชั่วโมงเท่านั้น (ห้ามผสม investing.com)
  cutoff ของ feature: แท่งที่จบแล้ว ณ 16:00 = แท่ง 10, 11, 12, (13), 14, 15
  ห้ามแตะ           : ทุกค่าของแท่ง 16:00
  ห้ามใช้           : Volume ของแท่ง 10:00 · แท่ง 13:00 เป็น feature บังคับ
  วันที่ไม่ครบ      : ตัดทิ้งทั้งวัน ห้าม ffill
  ขนาดตัวอย่าง      : ~720 วัน -> โมเดลความจุต่ำ, ANN ต้องเล็ก + L2 จริงจัง
  การประเมิน        : walk-forward ภายใน 722 วัน -> freeze -> prospective (ข้อ 4)

แนว A
  target   : close_bar16(t) / close_bar15(t) - 1
  baseline : Naive = "close_bar16 = close_bar15"
  feature  : return ระหว่างแท่งของวันนี้, ช่วงแกว่งของวันถึง 15:00,
             ตำแหน่งราคา ณ 15:00 ในกรอบวัน, volume แท่ง 11-15,
             day-of-week (ไม่ต้อง shift)

แนว B2
  target   : close_bar16(t+1) / close_bar15(t) - 1
  baseline : Naive = "ราคาปิดพรุ่งนี้ = close_bar15 ของวันนี้"
  feature  : feature แบบรายวัน (return lags, MA ratio, volatility, RSI ฯลฯ)
             ที่ "สร้างจากไฟล์รายชั่วโมงเดียวกัน" (รวมแท่งเป็นรายวัน)
             + feature intraday ของวันนี้ถึงแท่ง 15:00
             *** ห้ามดึง feature รายวันจาก raw_data/ (investing.com) ***
  หมายเหตุ : ประวัติมีแค่ 722 วัน และ rolling window ยาว ๆ จะกินวันต้นชุดไปอีก
```

**ข้อจำกัดที่ต้องเขียนในรายงาน:**

1. คนละแหล่งกับโมเดลรายวัน (ต่างเฉลี่ย 0.33–0.69 บาท) → เทียบตัวเลขข้ามโมเดลไม่ได้
2. แนว A: horizon สั้นกว่ามาก → MAE/R² ดูดีโดยไม่ได้แปลว่าเก่งกว่า
3. แนว A: remaining move เฉลี่ยต่ำกว่าต้นทุน แต่มีบางวันที่เกิน → ประเมินรายสัญญาณ
4. ความหมายของ timestamp / `close_bar16` — **ยังไม่ได้ยืนยัน** (ไม่มีไฟล์ Yahoo 1d)
5. ไม่มี historical test — ตัวเลขก่อน live เป็น walk-forward บน development data
