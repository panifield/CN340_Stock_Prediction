# โปรเจกต์ทำนายราคาหุ้นด้วย ANN และ Machine Learning

3 งาน × 3 โมเดล (ANN + ML ดั้งเดิม 2 ตัว) พร้อม baseline ครบทุกงาน

---

## วิธีรัน

โปรเจกต์นี้แยกเป็น 3 โฟลเดอร์อิสระต่อกัน **อย่างสมบูรณ์**
`task_a/`, `task_b/`, `task_c/` — แต่ละโฟลเดอร์มี config, feature,
target, โมเดล, baseline, evaluate, diagnostics, `data_cache/`,
`raw_data/`, `results/` เป็นของตัวเองทั้งหมด ไม่ import ข้ามโฟลเดอร์
กันเลย แก้ feature หรือพารามิเตอร์ของงานไหนก็ไม่กระทบงานอื่น

```bash
pip install -r requirements.txt

cd task_a && python main.py     # งาน A: คู่/คี่
cd task_b && python main.py     # งาน B: ราคาปิด (return)
cd task_c && python main.py     # งาน C: ขึ้น/ลง
```

ครั้งแรกแต่ละโฟลเดอร์จะโหลดข้อมูลจาก Yahoo Finance แล้วเก็บไว้ใน
`<task>/data_cache/` ของตัวเอง (ครั้งต่อไปอ่านจาก cache เลย เร็วขึ้นมาก)
ผลลัพธ์จะถูกบันทึกเป็น csv ในโฟลเดอร์ `<task>/results/`

ใช้ `--dev` ตอนกำลังปรับ feature/พารามิเตอร์ (`python main.py --dev`)
เพื่อเทรน+ประเมินบน train/val เท่านั้น ยังไม่แตะ test

**ถ้ารันไม่ได้เพราะเน็ต** ให้เปิด `config.py` ของโฟลเดอร์นั้นแล้วตั้ง
`USE_SYNTHETIC_DATA = True` เพื่อทดสอบว่าโค้ดทำงานได้
(แต่ห้ามเอาผลจากข้อมูลจำลองไปใส่รายงาน)

หมายเหตุ: บทวิเคราะห์ "เชื่อมงาน A กับ B" (heuristic ประมาณ accuracy
งาน A จาก RMSE ของงาน B) ไม่มีอยู่แล้ว เพราะต้องใช้ผลจากทั้ง 2 งาน
พร้อมกัน ซึ่งขัดกับการแยกรันอิสระ — ถ้าต้องการวิเคราะห์ส่วนนี้ต้องรัน
task_a และ task_b แล้วเอา `best_rmse_baht` จากงาน B ไปคำนวณเอง

## โครงสร้างไฟล์ (เหมือนกันทั้ง 3 โฟลเดอร์ task_a / task_b / task_c)

แต่ละโฟลเดอร์มี `README.md` ของตัวเองอธิบายละเอียดเฉพาะงานนั้น
(feature/target ที่ใช้, โมเดล, baseline, จุดที่ต้องดูก่อนเขียนรายงาน)
ตารางด้านล่างเป็นภาพรวมกว้างๆ ที่เหมือนกันทั้ง 3 โฟลเดอร์

| ไฟล์ | หน้าที่ | แก้เมื่อไหร่ |
|---|---|---|
| `config.py` | ค่าตั้งของงานนี้ | อยากเปลี่ยนหุ้น / พารามิเตอร์โมเดล / สัดส่วน split |
| `rounding.py` *(task_a เท่านั้น)* | ปัดเศษตามกฎอาจารย์ + คู่/คี่ | อาจารย์เปลี่ยนกฎการปัด |
| `data_loader.py` | โหลดข้อมูล + ทำความสะอาด | เปลี่ยนแหล่งข้อมูล / ใช้ไฟล์ csv เอง |
| `features.py` | สร้าง feature + shift กัน leak | อยากเพิ่ม/ลด indicator ของงานนี้ |
| `targets.py` | สร้าง target ของงานนี้ | เปลี่ยนนิยาม target |
| `splits.py` | แบ่ง train/val/test ตามเวลา | อยากใช้ walk-forward |
| `baselines.py` | baseline ของงานนี้ | เพิ่ม baseline ใหม่ |
| `models.py` | นิยามโมเดล ANN + ML อีก 2 ตัว | เปลี่ยนโมเดล / สลับไปใช้ Keras |
| `evaluate.py` | คำนวณ metric + ตาราง | เพิ่ม metric |
| `diagnostics.py` | วิเคราะห์ข้อมูลก่อนเทรน | — |
| `main.py` | ตัวหลัก เรียกทุกอย่าง | เปลี่ยนขั้นตอนการทดลอง |

| งาน | ประเภท | ANN | ML #1 | ML #2 |
|---|---|---|---|---|
| A. คู่/คี่ | Classification | MLP | Random Forest | XGBoost |
| B. ราคาปิด | Regression | MLP | Random Forest | XGBoost |

(เชิงเส้น / tree-based / neural network) ไม่ใช่โมเดลคล้ายกัน 3 ตัว

## 5 จุดที่โค้ดนี้ป้องกันไว้ให้แล้ว

**1. `round()` ของ Python ไม่ตรงกฎอาจารย์**
Python ใช้ banker's rounding: `round(143.5) = 144` แต่กฎ "เศษ > 0.5 ปัดขึ้น" ต้องได้ 143
ถ้าใช้ `round()` ตรงๆ ราคาที่ลงท้าย `.50` จะกลายเป็นเลขคู่หมด = ยัด bias เข้า target
โค้ดนี้เขียนฟังก์ชันเอง คำนวณในหน่วยสตางค์ พร้อม self-test

**2. Data leakage**
Feature ทุกตัวถูก `shift(1)` ทีเดียวตอนท้าย และมี `verify_no_leak()`
ที่เช็คจริงว่าแถว t มีค่าเท่ากับ indicator ของแถว t-1

**3. Tree model ทำนายราคาดิบไม่ได้**
RF/XGBoost extrapolate ไม่ได้ ถ้าเทรนช่วงราคา 100-150 แล้ว test ที่ 200
จะทำนายตันอยู่ที่ 150 โค้ดนี้จึงทำนาย **return** แล้วค่อยแปลงกลับเป็นราคา

**4. ไม่มี baseline**
ทุกงานมี baseline อยู่ในตารางเดียวกับโมเดล ตัวสำคัญคือ
- งาน A: **persistence** (parity วันนี้ = เมื่อวาน)
- งาน B: **naive** (พรุ่งนี้ = วันนี้)
- งาน C: **majority / always-up**

**5. Shuffle ข้อมูล time series**
`splits.py` ของแต่ละงานแบ่งตามเวลาเท่านั้น และมี assert ตรวจว่าช่วงเวลาไม่ซ้อนทับกัน

## สิ่งที่ต้องดูก่อนเขียนรายงาน

รันแล้วดูส่วน "การวิเคราะห์ข้อมูลก่อนเทรน" ก่อนเลย ตัวเลขสำคัญคือ

- **Flip rate** ของงาน A — parity เปลี่ยนจากเมื่อวานกี่ %
  ถ้าต่ำกว่า 35% แปลว่า parity เหนียว โมเดลจะได้ accuracy สูงหลอกๆ
- **จำนวนค่าสตางค์ที่พบ** — ถ้าน้อยกว่า 4 แบบ แปลว่าติด tick grid
- **วันที่ราคานิ่งเป๊ะ** — ถ้าเกิน 5% ควรพิจารณาตัดออกจากงาน C

## ข้อเสนอโครงรายงาน

1. **บทนำ** — โจทย์ 3 งาน, สมมติฐานว่าตลาดมีประสิทธิภาพหรือไม่
2. **ข้อมูลและ Feature** — หุ้นที่เลือก, ตาราง feature, การป้องกัน leakage
3. **การวิเคราะห์เบื้องต้น** — tick size, base rate, flip rate
   (ส่วนนี้แหละที่จะทำให้รายงานดูแข็งแรง)
4. **ผลการทดลอง** — ตาราง 3 งาน พร้อม baseline ในตารางเดียวกัน
5. **บทวิเคราะห์**
   - งาน A: ถ้าชนะ baseline ไม่ได้ = ไม่มี pattern จริง โยง EMH
   - งาน B: R² สูงแต่แพ้ naive = ตัวเลขสวยไม่ได้แปลว่าโมเดลดี
   - งาน C: มี edge เล็กน้อยไหม พอหักค่าคอมมิชชั่นหรือเปล่า
   - **เชื่อมงาน A กับ B**: parity พลิกทุก 1 บาท ถ้า RMSE ราคา > 0.5 บาท
     สัญญาณจะถูกกลบไปเกือบหมด (โค้ดคำนวณให้แล้วในส่วนท้าย)
6. **สรุป** — โมเดลไหนดีที่สุด และ "ดีพอจะใช้จริงไหม"

## หมายเหตุเรื่อง tick size ของ SET

ตัวเลข tick size ที่อ้างในคอมเมนต์ (10-25 บาท → 0.10, 25-100 → 0.25,
100-200 → 0.50, 200-400 → 1.00) ควรเช็คกับประกาศตลาดหลักทรัพย์อีกรอบ
